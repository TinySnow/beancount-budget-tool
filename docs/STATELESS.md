# 维持现有两份 YAML，不保存独立审阅记录

日常只维护 Beancount 账本、原来的 `config.yml` 和 `budgets.yml`。不新增配置层或字段。程序重新核验这些输入，能证明时认证；存在歧义就待审，由用户修改账本或现有配置后重算。

用户在2026-10-28的补充原文否决新增顶层块和继续复杂化配置（1ab95c85、ead650d1）。此前9d13e31虽删除隐藏状态并通过技术测试，却加入了被否决的 `declarations`；该扩展已撤销，其CI绿色不能视为满足最终产品合同。

## 现有输入与操作

- 资产用途写posting的 `fund`；费用、收入及负债责任写 `budget`；专题写 `tracking`。
- 账户H/K、支付范围、必要期初用途、默认规则及负债角色继续使用config.yml现有字段。
- 消费/用途目标和真实工资周期继续使用budgets.yml现有字段。
- 月末完整性继续使用该月份原有的 `completeness_confirmed`；未确认时省略或为false，不能放在跨月默认层。

```yaml
schema: 1
months:
  "2024-09":
    completeness_confirmed: true
    expense_targets:
      生活开销: "3000"
```

TUI的e只显示来源和修改指引，f只显示月末YAML填写指引。它们不输入批准、理由，不保存决定，不修改用户文件。编辑器保存后按r或watch重算。历史、日末、失败划拨前h诊断、区间、工资周期、交易详情及导出保留。

config和budgets都不接受新增的 `declarations`，空块也会报配置错误。没有另一套外部认领表或程序批准路径。

## 歧义和复杂协议

不因删除隐藏状态而降低财务核验。精确金额守恒、责任容量、同日先后、成本/批次、来源身份和未来截止日隔离继续生效。

现有标签和规则能表达的普通负债、多用途合并划拨、组合转账、申赎等继续正常计算。无法唯一推断的外部认领、人工经济组、未知先后结算、额外责任证据或证券池协议，在既有输入不能表达时保持待审或明确暂不支持；不增加字段，不猜测批准。待审结果不含局部正式财务数字。

## 旧文件与显式迁移

旧 `.budget-state` 原样保留，程序不读取、不监听、不导入、不更新、不删除。旧reviews的存在、损坏或内容变化不影响当前查询；原来仅靠隐藏批准才能认证的月份，没有当前公开依据就待审。

state、clean、review等保存命令退役，状态存储模块、save_snapshot API及浏览器show_saved_month/saved分支已删除。旧批准适配只保留为内部财务协议fixture的兼容验证，普通入口不可达；发行包排除state_store、review、obligation_review、month_actions、project等旧适配。

`configure --from-config`只处理用户明确提供的旧month.yaml，不搜索reviews。普通账户、目标和月末字段可转换为现有两文件字段，旧源不变。若旧配置含不能表达的外部claim、责任事件/期初、结算、经济组、资金池等证据，报 `SIMPLE_IMPORT_UNSUPPORTED` 且不产生输出；不能静默删除证据后认证。能用账本标签解决的请修改标签，不能表达的协议暂不支持。

迁移不保留手工注册ID或任意旧理由：名称生成当前确定性ID，月末true生成当前声明文档，因此旧多文件迁移后的文档摘要可改变。金额、目标和来源核验必须保持；摘要对应实际生成文档字节。日常已有两文件输入不受这项迁移差异影响。

内部schema6文档只是内存/系统临时适配，不是第三份用户配置，不写回用户目录。证据摘要按平台实际YAML写入字节生成，LF/CRLF合同保留。
