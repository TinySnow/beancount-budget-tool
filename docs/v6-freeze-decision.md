## 2. 容忍性退让台账（可以带着这些开始写代码）

退让规则（写进冻结声明）：**退让只允许三种形态——拒绝、待审/未知、范围收窄；任何退让都不得表现为"近似数字"、"默认猜测"或"补齐后照算"。** 需要更宽支持时，先给具体反例，修订 v6 规范与验收用例并显式版本化，再实现；不能原地放宽旧语义。

| # | 可退让项 | 首版可以怎么做（安全形态） | 何时必须升级 |
|---|---|---|---|
| T1 | 侧文件与声明的具体编码（YAML/JSON 字段名、CLI 交互） | 由实现自由固定并版本化 | 只影响兼容性，不影响正确性 |
| T2 | 计划生命周期（延期、改额、版本链） | 只实现批准/兑现/取消＋版本号；延期与改额**拒绝** | 用户需要改额历史回放时 |
| T3 | 多计划联合模拟 | 首版**只支持单计划**；多计划未实现时以 `UNSUPPORTED_EVENT` 明确拒绝，只有已证实争用同一来源容量才报 `PLAN_SOURCE_OVERALLOCATED` | 用户实际需要多计划共同计算时 |
| T4 | 在途结算（银行已扣、发卡方未销账） | 无独占有效证据即**待审并暂停该首页数字** | 用户要求日常看到在途状态 |
| T5 | 分期/最低还款/逾期的自动推导 | 首版由人给出"本月必须偿付"切片，机器只校验守恒；自动推导拒绝 | 需要自动化账单解析时 |
| T6 | 多用途卡债的清偿分配 | 首版**逐笔指定**；FIFO/按名猜测拒绝 | 用户要求批准式批量规则时 |

| T8 | 外币"当前清偿价"、期末市值 | 无时点报价即待审；**不套历史价与今日汇率** | 接上行情/账单来源时 |

| T10 | 缓存、代际 ID、增量重算等性能机制 | 首版可**全量重算**；源文件不变但 `as_of`、到期、报价有效期或政策版本变化也必须重算，不得只看源哈希 | 数据量或交互时延需要时 |
| T11 | 迁移提案的自动化程度（旧标签→类别/用途/专题/计划） | 只出**待审建议**＋批量确认；不得自动批准 | 交互体验阶段 |
| T12 | 混合基金历史期初的用途归属不完整 | 保留"用途未知"状态，已知部分另名显示 | 拿到份额/对账资料时 |
| T13 | 证券/外币整体不进首页 | 声明式排除＋同屏理由，合法而非降级 | 用户要求首页含证券时 |

## 3. 绝不可退让的 6 条（退让即失去准确性主张）

1. 责任按身份去重与覆盖守恒（`实际可花 = 自由现金 − Σ去重后未覆盖责任`）。
2. 报告时点与到期/逾期进入计算输入，且并列数字同点。
3. 计划来源身份、容量与净增量；不得把计划当现金。
4. 未标注资产腿默认待审；`fund:"-"` 不等于可支付。
5. 跨投影去重（同一来源切片不得既冲费用又补收入），且**不得**用"同额即同一事件"自动合并。
6. 不得为预算编造 Beancount 事实或基金持仓；基础 loader 错误与守恒失败一律阻断签发。
