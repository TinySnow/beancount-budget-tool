# 建议补充到手写需求的界面与数据管理条款

本页供需求作者选择、修改后写入 REQUIREMENTS.md。原手写文件保持不变；以下调整用户入口，不重定义费用、用途、净划拨或可花金额。

## 建议条款

1. 日常配置由一份 config 与一份 budgets 组成，直接使用中文名称；用户不维护内部 ID、来源哈希或编译文件，也不逐月复制配置。
2. 账本明确的 fund／budget 名称可自动发现。自动登记名称不等于批准不确定资金流向；缺失用途、金额不守恒或证据不足必须给出原因及文件行号。
3. 修改账本或配置后可直接重算。结果为已核对报告，或明确范围的待审结果；若只完成配置预检，应说明交易尚未检查。实现缺项与数据待审分开。
4. 预算文件只定义目标，不凭计划创造资金或自动兑现。0、未决定和不考核应明确区分；工资周期额度与自然月目标独立。
5. 切换月份复用稳定规则与原 cutover，余额重放结转；不自动把某个月的资料完整性／债务证据认作其他月也已确认。
6. 可重建输入正常结束后自动清理。已审决定、月末确认和必要恢复资料由程序保存，用户只备份、不手工拼接或维护。清理不能造成已审数据丢失。
7. Windows 目录版 exe 的依赖与用户数据分开说明；不得把删除运行依赖作为简化方案。

## 当前实现边界

两文件入口、直接切月、自动登记明确用途、缓存生命周期、压缩审阅状态及清理命令已实现。复杂协议的新建表单、失效旧认领的统一 TUI 处理仍未全部覆盖，暂保留高级导出／导入入口；不能写成所有交易都已能仅用普通字段自动处理。

如果保留原需求中交易和计算例子，无需因这次内部存储重构整体重写。主要应补充「用户操作与数据管理」一节，使实现不能再次把内部审计结构转嫁成日常人工步骤。
