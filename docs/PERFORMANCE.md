# 性能测量与复用边界

本轮以 `be965c3` 为基线，保留原有来源引用、精确金额、完整性声明、责任守恒和签发规则。以下为本机 Python 3.14 / Beancount 3.2.3 的观察值，不作为跨机器的耗时保证。

| 场景 | 基线 | 优化后 |
|---|---:|---:|
| 合成 1000 笔消费，已认证月报，无交易详情 | 约 0.50 秒 | 0.35–0.38 秒 |
| 约 690 文件 / 8600 交易，2026-09 待审月报，含交易详情 | 0.96–0.98 秒 | 0.84–0.91 秒 |
| 同一账本、月份，TUI 再次刷新 | 0.96–0.98 秒 | 0.32–0.37 秒 |

真实账本只读测量；2023-09、2025-09、2026-09 的完整 JSON 在统一随机临时目录路径后与基线一致。另将九例连续验收放在相同路径分别执行基线与优化版，2026-10、2026-11、2026-12 三份已认证 JSON 完全一致，无需路径正规化。待审场景与已认证场景分别测量，不能用某个待审月份的耗时推断所有月份。首次 TUI 刷新仍需完整解析，复用收益主要体现在切月、重算与保存审阅后的后续刷新。

独立审阅复测确认：7 个月份及一个三个月区间的 JSON 与基线一致；同尺寸同 mtime 修改金额、修改预算目标和新增 glob 成员后，TUI 均失效重算并与基线相同。其两组真实账本 TUI 后续刷新耗时分别减少约 66% 和 69%，合成 1000／5000 笔已认证月报分别减少约 21%／22%。首次建立内存序列化副本会增加开销：一组已认证场景首次刷新由 0.794 秒增加至 0.851 秒，约慢 7%；不应把后续刷新收益当作首次启动收益。

最终独立复核与本地完整测试均为 1046 项通过。独立复核还确认公开连续验收三个月 JSON／文本逐字节相同，以及真实账本 2026-01 至 09 区间报告正规化运行目录后完全相同；该九个月区间由 3.91 秒降至 2.85 秒，约减少 27%。并非每个单次审计都更快：2023-07 已认证单月从 0.66–0.67 秒变为 0.71–0.74 秒。这一轮主要改善后续 TUI 刷新与区间查询，不能宣称所有单月和首次加载都提速。

追加 2023-07 复测启用了账本路径写入拦截，并前后核对全部非 Git 文件清单与摘要：863 个文件完全一致。各建立三个新 browser，其首次刷新中位数由 0.730 秒增至 0.797 秒（约慢 9%），第二次刷新由 0.732 秒降至 0.189 秒（约减少 74%），完整 JSON 摘要一致。写入拦截本身也有开销，这组值只用于同组前后比较。

## 改动

- 在同一冻结输入内复用持仓、历史计价、H 转账、外汇、收益、K 事件和配置盘点，避免重复遍历与标签解析。
- 审计结果继续复制后交给调用方；常见字典、列表与不可变标量使用轻量复制，其他类型回到标准 `deepcopy`。共享引用、循环和容器子类保留原行为。
- 来源引用的相对路径按文件计算一次；交易摘要、fact 摘要、重复交易 occurrence 和 claim 格式不变。
- TUI 显式持有最多一份完整解析的进程内副本。复用前核对文件内容、路径别名和 glob 成员，内容变化则重新解析。每次恢复独立的可变分录元数据和 options、创建新的审计缓存，再按当前截止日筛选；不保存月度结论。
- CLI、独立审计默认仍重新解析；不新增持久化缓存、mtime 信任或缓存目录。

## 复现

在项目根目录运行，解释器须已安装项目依赖：

```sh
python benchmarks/month_report.py --transactions 1000 --repeats 3
python benchmarks/month_report.py --config /path/to/config.yml --month 2026-09 --details
python benchmarks/month_report.py --transactions 1000 --profile /tmp/budget.prof
python -m pstats /tmp/budget.prof
```

脚本只打印耗时、状态和输出摘要。合成账本在临时目录；已有配置、账本及签发记录均不写入。`audit` 测量不含 Python 解释器启动，`browser` 区分首次加载与后续刷新。前后版本对照应串行执行，避免并行测试占用 CPU。

回归检查覆盖同大小／同 mtime 内容修改、glob 新增／删除、路径别名切换、loader 版本、截止日隔离、运行中修改拒绝输出、配置内容失效及可变结果隔离；现有责任、来源审阅和签发测试继续执行。
