# v6统一主线、两项功能与执行层重构

**历史阶段记录：**本文记录0a8903c及之前的stateful等价统一、旧状态兼容和当时的1091项验证。用户随后明确要求去除运行时reviews；当前产品合同及后续实现见[STATELESS.md](STATELESS.md)，不能用本文历史CI替代无状态验收。

## 合并决定

后续统一维护`codex/v6-implementation`，源码放在`beancount-budget-tool`主目录。原来的重构副本与`dpsk/v6`不再独立开发。此次沿用完整v6财务规则、配置、审阅状态和界面，只替换执行与数据访问层；没有用功能较少的轻量引擎覆盖完整规则。

原v6的两项功能提交保留在历史中：

- `5a8f71f`：H用途主动划拨透支后，可从TUI错误页按`h`或通过`history --before-source 文件:行号`查看失败交易之前的用途流水。输出明确为`DIAGNOSTIC_ONLY`，不含失败交易及后续补款，不签发月报或最多能花。
- `2cc0f44`：同币种H转账允许明确的多用途合并到单一用途；逐用途扣减并核对精确守恒。混合到混合的歧义、来源不足、金额不等、费用或FX协议仍按既有规则拒绝或待审。

工作区原有性能补丁先以`16320e9`单独保存，再合入完整执行层重构，不覆盖两项功能或丢弃未提交成果。

## 执行架构

1. 一次官方语法解析，同时捕获来源manifest与原始文本证据；继续使用固定版本Beancount的官方booking、转换及验证。
2. 独立重建include可达闭包，核对别名映射、物理来源、glob成员与内容。入口、会话退出时验证，不信任大小/mtime作为内容证明。
3. 完整快照共享稳定引用与事实索引，有界查询只暴露截止日前事实。保留raw transaction hash、occurrence、posting/booked ordinal、lot/fact以及pad引用合同。
4. 普通只读计算直接消费内存运行文档；审阅编辑、状态导出等写入适配仍保留。用户继续维护相同的两文件配置。
5. QuerySession管理输入、索引和投影生命周期。内部结果递归只读；公开出口返回隔离的普通可变容器。解析缓存仅在RAM中使用私有payload，每次返回隔离AST/options/meta，首次调用也不共享可变对象。
6. 账户源盘点、用途声明和行内切片准备按同一快照视图复用；声明overlay、期初容量、负库存与带/不带opening的重放仍独立执行。

这属于执行层重构，不宣称所有金融规则已改写为单次重放，也不宣称总代码行数减少。

## dpsk分支借鉴结果

审阅对象为`dpsk/v6`的`ec79361`，尤其是`bgbudget/bgbudget/{cache,cli,lite,engine}.py`。

| 设计 | 处理 |
|---|---|
| 单引擎与不同展示视图 | 保留完整规则，由统一查询服务和TUI/报表适配，不再维护第二套金融规则 |
| 按需加载命令模块 | 沿用主launcher已有的命令路由，并将分项审计的财务模块导入延后到参数解析之后；帮助与参数错误不加载Beancount |
| 来源解析复用 | 采用完整内容/闭包验证与RAM隔离缓存；不复制size/mtime指纹和磁盘pickle |
| 轻量规则省略证明或状态 | 不采纳；少计算不是完整功能下的等价提速 |
| 独立可执行分发 | 保留v6现有PyInstaller、Unicode与平台验收流程 |

审计帮助命令在五次独立进程测量中，中位数约77.6ms→39.1ms。这只代表`audit --help`启动，不代表月报计算提速。较大的月报/区间收益来自前两轮执行层重构，详情见[REBUILD.md](REBUILD.md)与[ROUND2-PERFORMANCE.md](ROUND2-PERFORMANCE.md)。这些文档中的副本路径和提交是历史测量对象。

## 明确的输出变化

生成配置文件不再作为公开来源暴露。区间的`months[*].config`改为实际用户`config.yml`；部分过期人工claim诊断也从已经删除的临时`compiled/ownership.yaml:行号`映射到实际用户配置。错误码、错误正文和拒绝行为不变。这是来源展示修正，不修改金额、认领身份或批准内容。

默认规则与逐笔认领不同：仅修改一笔可自动推断的金额会重新计算报表，不必把规则本身判为过期；修改已人工绑定的交易则拒绝旧claim。交易外空行/注释也不应使稳定交易身份变化。
